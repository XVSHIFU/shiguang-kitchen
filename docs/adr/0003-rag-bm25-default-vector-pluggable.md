# ADR-0003：RAG 默认纯 Python BM25，向量检索可插拔

- 状态：已采纳
- 日期：2026-11-18

## 背景

设计文档 §9 要求 BM25 + pgvector + RRF 混合检索，并指出 pg_search 社区版为
AGPL-3.0、部署前须完成许可证审查；同时严禁向量相似度查询精确营养数字。

## 决策

- 默认只实现纯 Python BM25（`app/rag/bm25.py`，标准 k1=1.5/b=0.75，中文按字
  + 二元组分词），检索对象为 `knowledge_docs`（16 菜谱 + 10 条通用饮食指导），
  返回带 source 引用的结果。
- 向量检索为可插拔适配器：未配置 `EMBEDDING_*` 时明确禁用，并在检索响应中
  返回 `vector_enabled: false` 与说明；绝不因无 embedding 而伪造向量分数。
- 营养数字永远走结构化查询（`nutrition_of_food_items`），不经过任何检索路径。

## 后果

- 优点：零外部依赖、无许可证风险、检索行为完全确定可测。
- 代价：无语义召回；同义词/口语查询的召回弱于向量方案。后续接入 embedding 时，
  需锁定模型与维度并全量重建索引（不同模型向量不得混排），再以同一评测集做
  新旧对照。

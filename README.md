# 食光管家

用一套工具记录家里的食材、安排菜单、记下吃了什么，再回看这一周的饮食和生活习惯。AI 管家可以根据库存给建议，菜单变更由你确认后生效。

界面采用焦橙、蜂蜜黄和浅米灰配色，支持浅色和深色模式。

## 快速体验

准备 Python 3.12，在项目根目录打开终端。应用使用本地 SQLite 数据库，浏览器直接打开服务地址。

### Windows PowerShell

请确认终端里的 `python` 是 3.12。使用 uv 管理 Python 的用户可用 `uv venv --python 3.12 --seed backend/.venv` 建环境，然后执行安装和启动命令。

```powershell
python --version
python -m venv backend/.venv
& .\backend\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
& .\backend\.venv\Scripts\python.exe scripts/run_local.py --demo
```

### Linux

```bash
bash scripts/run_local.sh
```

启动后打开 [http://127.0.0.1:8014/](http://127.0.0.1:8014/)，点「一键填入演示账号」并登录。演示账号是 `demo@example.com`，密码是 `Demo1234!`，里面有示例库存、菜单和记餐记录。

### 用自己的账号

在一个新的数据库中启动时，运行 `python scripts/run_local.py` 会加载共享食材和菜谱目录。打开页面后选「注册」，再填写自己的库存、忌口和烹饪设备。请使用前面步骤中创建的虚拟环境解释器执行这条命令。

数据库默认保存在 `backend/data/app.db`，配置在项目根目录的 `.env`。首次启动会从 `.env.example` 生成配置并执行数据库迁移。再次启动会继续使用同一份数据。

## 从哪里开始

| 我想做什么 | 去哪里 |
| --- | --- |
| 看今天吃什么、记一餐 | 首页的餐盘可以按早、午、晚点选。点击「吃了」后保存，计划餐会计入菜单和周报。 |
| 知道哪些食材快过期 | 打开「食材冰箱」，按食材批次查看数量、储存位置和到期时间。 |
| 给这周换菜或补买东西 | 从「菜单计划」调整餐次，核对「购物清单」，收货确认后可入库。 |
| 跟着步骤做菜 | 菜谱详情可进入烹饪模式，逐步查看做法、计时和朗读。 |
| 换点不一样的口味 | 首页点「换个胃口」，用转盘或盲牌挑选地方菜、小吃和甜品。 |
| 回看一周 | 在「生活习惯」记录饮水、睡眠、步数或体重，到「周报」生成或更新这周的回顾。 |
| 让 AI 帮我想菜 | 打开「AI 管家」提问。建议可以继续追问，修改单可以查看、调整和审批。 |

保存计划或记餐默认只登记对应记录。库存扣减发生在你确认烹饪消耗或主动登记库存消耗时。营养量依据食材库和份量计算，缺少来源时会标记「部分已知」。

## 配置 AI 管家

打开根目录的 `.env`，填写模型提供方发给你的密钥、接口和实际模型名。按你的账号支持的模型填写。配置后重启，到「设置 → Agent 模型」测试连接。

| 设置 | 用途 |
| --- | --- |
| `MODEL_API_KEY` | 模型 API 密钥。留空时管家使用规则模式。 |
| `MODEL_BASE_URL`、`MODEL_NAME` | OpenAI 兼容接口地址和文本模型名。 |
| `MODEL_VISION_NAME` | 拍照识别所用的图像模型。识别结果会先作为候选显示。 |

模型模式会把回答所需的上下文送给已配置的模型服务。语音输入和朗读依赖浏览器的支持与权限。

### PostgreSQL 换餐审批

已有 PostgreSQL 数据库时，可在根目录的 `.env` 中填写 `.env.example` 里的 PostgreSQL `DATABASE_URL`，再按上面的方式启动。数据库账号需要在目标库中建表，启动时会执行业务迁移并初始化 LangGraph 检查点。SQLite 和 PostgreSQL 各自保存数据。

AI 管家提出换餐后，你可以重启应用，再打开原对话审批同一张修改单。审批通过时，系统会检查当前菜单版本，再保存新的菜单版本。拒绝或遇到版本冲突时，菜单修改不会生效。[后端验证方法](backend/README.md#postgresql-换餐审批)

## 自动周报和数据备份

- Windows 或普通前台运行时可直接在「周报」手动生成。Linux 部署可启用随项目提供的定时器。定时器每周日北京时间 20:00 运行，为授权「自动」的账号生成周报并发站内通知。
- 在「设置 → 隐私与数据」可以导出个人数据。SQLite 整库备份和恢复由服务器管理员操作，恢复后需要重新登录。

常驻部署、管理员开通、备份和定时器的操作步骤见 [Linux 部署与运维](deploy/LOCAL_LINUX.md)。

## 启动遇到问题

- 查看启动终端的报错，并检查 [健康状态](http://127.0.0.1:8014/health/ready)。端口被占用时，在启动命令后加 `--port 8016`。
- 请通过上面的服务地址打开页面。登录、数据接口和 AI 流式回复由同一个服务提供。
- 想体验示例库存时，确认首次初始化使用了 `--demo`。模型显示规则模式时，检查根目录 `.env` 的配置并重启。
